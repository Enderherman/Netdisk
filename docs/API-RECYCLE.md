# 回收站策略与接口

本版本把原先“所有恢复项统一回根目录”改为“优先恢复原目录，原目录不可用时回根目录”。旧测试中两条恢复位置断言随此契约明确更新，其他权限、树遍历、永久删除与共享存储保护继续保留。

## 恢复规则

`POST /recycle/recoverFile`，参数 `fileIds` 为逗号分隔的本人回收站项。

- 原目录及其所有祖先属于本人、仍是正常文件夹时，恢复到原目录。
- 原目录缺失、已删除、类型不是文件夹、祖先不可用或存在异常循环时，恢复到根目录。
- 同批恢复父项和此前独立回收的子项时，子项留在恢复后的父树中。即使父项因原祖先缺失而回根，也不会把子项拆到根目录；提交顺序不影响正常树结构。
- 只恢复父项不会顺便恢复此前独立回收的子项。
- 名称冲突在实际恢复目标目录中解决，使用共同的 `FileNames` 规则，忽略大小写与组合重音，按 ` (1)`、` (2)` 分配唯一名称，保留扩展名；不同目录可保留相同名称。
- 恢复在同一用户锁和事务内完成，清除恢复项的回收时间，保持内部层级。损坏数据中跨选中项的环会被切断到根目录。

## 清空回收站

`POST /recycle/clear`，不接受用户 ID，目标来自当前登录用户。

返回 `data.deletedCount`，表示本次变为永久删除的文件及文件夹记录数（含回收子树）。空回收站或再次清空返回 0。只处理本人的回收站及回收子树，不处理其他用户，也不连带删除异常数据中的活跃节点。

永久删除后立即重新结算本人的数据库配额，并在事务提交后刷新缓存。这里不直接删除磁盘原件；物理清理继续交给既有 `ScheduledTask`，只有没有正常或可恢复引用时才能删除实体，并保持存储根和真实路径校验。其他用户通过秒传或转存共享的内容仍受保护。

现有 `POST /recycle/delFile` 接口继续用于永久删除所选项。交互写操作在获得用户行锁后再次确认账户启用；管理员已授权删除和后台期限清理可处理禁用账户的文件。

## 策略查询

`GET /recycle/policy`，要求登录，返回：

```json
{
  "retentionDays": 30,
  "autoCleanupEnabled": true,
  "restoreStrategy": "original_or_root"
}
```

`retentionDays=0` 表示关闭到期自动清理。全局清理关闭时，即使保留天数大于 0，`autoCleanupEnabled` 也为 false，前端应以该字段决定是否展示自动到期说明。

## 自动过期清理

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `netdisk.recycle.retention-days` | 30 | 非负整数；0 关闭自动过期。 |
| `netdisk.recycle.cleanup-cron` | `0 0 3 * * ?` | 每日 03:00 扫描。 |
| `netdisk.time-zone` | `Asia/Shanghai` | 自动过期调度默认使用北京时间。 |
| `netdisk.cleanup-enabled` | true | 全局定时清理开关。 |

按回收时间计算完整的保留天数，到达截止时刻即过期（包含等号）。只有回收站根项达到期限才进入永久删除；回收时间为空的异常记录保留。每位用户在独立事务中重新锁定并查询，以免扫描后已经恢复的文件被删除。禁用账户的到期回收数据仍可回收；单个用户失败不会阻断其他用户。

逻辑到期后文件从回收站消失、配额释放。实际磁盘空间在既有安全实体清理任务运行时释放，此任务不绕过共享引用或路径保护，也不自行执行另一套物理删除。

## 验证

`RecyclePolicyTest` 使用 H2、真实临时磁盘文件与 HTTP 接口验证原目录恢复、祖先失效回根、同批父子恢复、统一同名策略、空清空、用户隔离、日期边界、关闭策略、禁用账户、活跃节点保护，以及共享原件经过既有安全清理后仍可读取。

`RecycleServiceTest` 原有 13 项继续运行，其中“独立回收子项同批恢复”和“不同原目录同名项恢复”两项按新契约更新位置预期。测试环境关闭自动调度，显式调用期限任务，未接触生产存储。
