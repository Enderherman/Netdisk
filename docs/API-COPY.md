# 同用户文件与目录复制

## 接口

`POST /api/file/copyFile`，需要登录 Cookie，同源请求。表单参数：

| 参数 | 含义 |
| --- | --- |
| `fileIds` | 要复制的文件/目录 ID，逗号分隔，每次最多 1000 项；重复 ID 自动去重。 |
| `filePid` | 当前用户的目标目录 ID；`0` 表示根目录。 |

成功响应沿用 `{status:"success",code:200,message,data}`，`data` 为实际复制的顶层条目数组，字段与普通文件列表的 `FileInfoVO` 一致，包括新 `fileId`、最终 `fileName`、`filePid`、`folderType` 等。内部物理路径不会返回。选中目录及其子文件时，仅复制该目录一次。

前端可在成功后刷新目标目录与 `/getUseSpace`；返回的新条目可用于定位或高亮。该接口仅复制到当前用户的网盘，提交额外 `userId` 不会改变目标账户。分享转存仍使用 `/showShare/saveShare`。

## 行为

- 文件复制生成新条目；目录复制保留完整的正常目录树，最多 10000 个条目。源条目 ID、父目录、名称、时间及内容不变。
- 新条目引用已存在的不可变文件内容，不重复写入物理文件；逻辑容量按文件字节重新计费。源条目删除后，清理任务仍会保留副本引用的内容。
- 目标重名自动变为 `名称 (1).扩展名`、`名称 (2).扩展名`。名称通过 `FileNames.key/unique` 统一处理大小写及组合重音冲突；复制目录内部的旧重名也会规范化。
- 同时选择目录和目录中的文件时，只生成一个完整副本。复制到当前父目录允许并自动重名；将目录复制到自身或任意后代目录会被拒绝。
- 回收站、已删除、未完成处理的源条目不可选择；目录中已回收/删除的条目不会复活。源或目标目录链失效、循环、越权均拒绝。
- 批量复制、配额检查和容量更新在同一事务内执行；中途失败不留下部分副本，也不扣除容量。
- 空文件仍可复制，计费为 0 字节；当前额度刚好用满时也允许复制空文件。
- 复制与上传/缩容共用用户行锁；额度包含已提交文件、回收站占用和未完成上传的实际分片。复制还锁定源实体及其物理内容引用，避免与清理任务并发时复制陈旧记录。

## 错误

- `901`：未登录、登录失效或账号停用。
- `600`：参数、归属、目录位置、源状态或目录结构不合法。
- `904`：空间不足；整个批次没有新增文件。
- HTTP `405`：使用 GET 等不支持的方法。
- HTTP `403`：浏览器写入请求的 Origin/Referer 不可信。

分享转存与本接口使用相同的目录复制和配额结算实现，分享提取、有效期、取消等授权校验仍由分享接口负责。
