# 分片上传与完整性契约

## 完成后的文件定位（0.7.1）

任务的 `fileName` / `filePid` 保留最初上传参数，不能用于假设原件从未重名、改名或移动。完成且原件可用时，列表与详情另返回 `actualFileName`（当前名称）和 `navigationPath`（当前目录 ID 链，根目录为 `0`）。这不是磁盘路径。原件不可用或父链失效时该导航字段为 null；客户端应使用当前名称/目录定位，不用原始名称猜测。

接口：`POST /file/uploadFile`，使用登录会话和 multipart 表单。

| 字段 | 规则 |
| --- | --- |
| `file` | 当前分片的实际字节，不能缺失；单片上限 100 MB，仍受服务器请求大小配置限制。 |
| `fileId` | 首个请求不传或传空字符串。后端生成 10 位上传 ID；后续请求必须使用返回的 ID，不接受客户端自选 ID。 |
| `fileName` | 完整文件名，含扩展名，遵循文件组织接口的安全名称规则。 |
| `filePid` | `0` 为根目录；其他目标及其祖先必须是当前用户的正常目录。 |
| `fileMd5` | 整个原始文件的真实 MD5，32 位十六进制，不能使用单片摘要。 |
| `chunkIndex` | 从 0 开始。首个请求必须为 0，随后允许乱序。 |
| `chunks` | 总片数，1 至 10000；索引必须小于总片数。零字节文件只能使用一个分片。 |

文件名、目录、MD5 和总片数在任务建立后不可改变。需要改变时应创建新任务。旧版本没有任务凭据的未完成上传需要重新开始；本次不会把旧临时目录当作可信任务合并。

## 返回状态

- `uploading`：当前分片已接受，但尚未收齐全部分片。
- `upload_finish`：所有分片已按编号合并、校验真实 MD5，原件已就绪且数据库事务已提交。
- `upload_seconds`：当前用户已经拥有正常且可读取的同摘要原件，后端在实体引用锁下重新校验源文件实际大小和 MD5 后创建副本。

知道其他用户文件的摘要不能触发跨用户秒传。新文件的实际大小、摘要、物理路径和正常状态一次性入库，不存在“先计费、大小为空，后台稍后才写入”的窗口。

## 重试、缺片与失败

同一分片提交相同字节是幂等操作，不重复增加占用；同一编号换成不同内容会被拒绝。收到最后编号不代表完成，只有全部编号存在且大小和摘要通过校验才合并。缺失分片可以重新发送。

任务凭据记录在 `file/temp/{userId}/{fileId}/manifest.json`。完成后保留回执，已接受分片被清理；重复发送已接受的最终请求返回原结果，不重复创建文件或计费。回执必须对应数据库中已提交的正常文件，不能用过期回执复活已删除文件。

磁盘输入、写入或数据库失败都会明确返回失败，不会包装为成功的空数据。失败保留已接受分片，原件落库失败时只清理本次新建且确认未提交的实体，不递归删除任务目录。后续重复发送分片可继续尝试完成。路径校验覆盖 ID 格式、规范化根边界和真实路径，客户端文件名不会成为磁盘路径。

任务列表、断点查询、主动取消与到期清理已提供，见下文。失败或放弃的分片在成功取消或过期清理前继续占用临时额度。

## 配额与并发

上传、转存和配额决策使用同一个用户数据库行锁。已用额度来自文件记录，待完成占用来自该用户全部未完成任务的真实磁盘字节，不依赖 Redis 累加计数；已落库文件对应回执和已完成残留分片不重复计费。

分片接受和原件入库不能使“已用空间 + 全部待完成任务字节”超过总额度。转存同样先扣除待完成上传占用。合并过程中可能短暂同时存在分片与合并工作文件，因此部署磁盘仍需留出合并工作空间。

服务内部 `FileUploadService.pendingUploadBytes(userId)` 要求调用者已有数据库事务（MANDATORY），并重入同一用户行锁，供转存和管理员缩容使用。存储不可读时失败关闭，不能静默按 0 计费。

## 预览与处理状态

`file_info.status=2` 表示完整原件已就绪。图片使用 Java ImageIO 生成真实 JPEG 缩略图，限制解码像素数量；无法解码时保留原件、封面为空。不会把未知图片/SVG 原件复制成伪缩略图。

视频原件通过 `/file/content/{fileId}` 的 Range 接口播放；是否能直接播放取决于浏览器支持的编码。本次上传不依赖 FFmpeg，不生成虚假的 HLS 地址，不将派生处理失败误报为原件丢失。独立媒体派生任务和转码状态将在需要时单独实现。

## 验证

`FileUploadTest` 使用隔离 H2 数据库与 JUnit 真实临时磁盘目录，覆盖完整性、乱序、缺片、幂等、伪造 ID、元数据改变、用户隔离、秒传来源验证、实际临时配额、转存预留、数据库回滚、磁盘错误、Redis 故障、图片封面、空文件，以及并发完成和并发配额。

最终独立快照测试结果随本功能发布记录；验证不触及生产数据，未进行生产 MySQL 或多实例压力测试。

## 上传任务管理与续传

| 接口 | 方法与用途 |
| --- | --- |
| `/file/uploadTasks` | GET，本人任务分页列表；`pageNo` 默认 1，`pageSize` 默认 20、上限 100，均须为正数。可选 `state=uploading/completed/cancelled/expired`。 |
| `/file/uploadTask/{fileId}` | GET，本人任务详细状态，供刷新页面后续传查询。 |
| `/file/cancelUpload/{fileId}` | POST，取消未完成任务并清理分片，返回终止后的任务状态。 |

列表的数据为标准分页对象，具体查询及取消返回单个任务对象：

| 字段 | 含义 |
| --- | --- |
| `fileId/fileName/filePid/fileMd5/chunks` | 创建任务时固定的上传元数据，续传必须保持相同。 |
| `state` | `uploading` 上传中、`completed` 已完成、`cancelled` 已取消、`expired` 已过期。 |
| `uploadStatus` | 完成后的原始 `upload_finish` 或 `upload_seconds`，未完成时为空。 |
| `receivedChunks` | 仅详细查询返回 `{index,size}` 数组，按编号排序；列表中该数组为空。缺失或大小不匹配的磁盘分片不会被报告为可跳过。 |
| `receivedCount/receivedBytes` | 已接受分片数量/字节数。完成后为回执中的历史记录，不表示仍占用临时空间。 |
| `temporaryBytes` | 当前实际待清理的临时字节；已落库任务为 0。 |
| `fileSize/fileAvailable` | 已落库原件大小及当前是否可访问；回收或删除原件后不会复活它。 |
| `createdAt/updatedAt/expiresAt` | Unix 毫秒时间。上传中为最后一次有效分片活动的到期时间；已终止任务为回执保留截止时间。 |

续传流程：保留本地原文件与后端 fileId，GET 查询固定元数据和已接受编号，重新验证本地完整 MD5 后只发送缺失分片。已经完成的任务直接使用原件。已取消、已过期或回执被清理的 ID 不能重新创建任务。

取消与上传使用相同的任务文件锁和用户数据库行锁。取消重复调用是幂等的；取消若先完成，后续分片不会被接受；上传若已提交完成，取消会被拒绝，原件保持可用。释放的是临时数据，不能用取消接口删除已完成原件。

## 自动到期清理

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `netdisk.upload.task-ttl-hours` | 24 | 未完成任务的闲置小时数，允许 1 至 8760。每次接受有效分片后更新活动时间。 |
| `netdisk.upload.receipt-ttl-hours` | 168 | 完成、取消和过期回执保留小时数，允许 1 至 8760。 |
| `netdisk.upload.cleanup-interval-ms` | 300000 | 自动扫描间隔，同时作为首次执行延迟。 |
| `netdisk.upload.cleanup-enabled` | true | 上传任务自动清理开关，同时受全局 `netdisk.cleanup-enabled` 开关控制。 |

状态查询可先报告闲置任务已过期；定时任务会释放其临时数据，过期任务的上传请求也会立即终止并清理。完成回执到期只移除任务文件，不删除网盘原件。任务 ID 不能由客户端指定重建，因此清理回执后也不会复活旧上传。

清理只处理身份与目录对应的合法任务凭据，逐项核对存储根边界，不跟随链接，不递归删除未知目录。发现损坏凭据、未知文件或目录时保留该任务并记录失败，继续清理其他任务。禁用账户的过期临时数据也可自动回收。

`UploadTaskTest` 使用真实临时文件与 H2 验证用户隔离、续传、幂等取消、并发取消/完成、可配置 TTL、回执删除、禁用账户清理、损坏身份凭据与路径保护；测试环境关闭自动定时执行，测试显式调用清理方法。
